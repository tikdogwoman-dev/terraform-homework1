# Домашнее задание: Настройка окружений (Staging/Production) в Yandex.Cloud с помощью Terraform

В данном репозитории описана отказоустойчивая, масштабируемая инфраструктура для приложения в Yandex.Cloud с разделением на независимые контуры (**staging** и **production**). Вся конфигурация разделена на логические файлы и полностью адаптирована под современную зону доступности `ru-central1-d` (Калуга).

## 🌍 Организация окружений и привязка к коду

Разделение инфраструктуры на тестовый (staging) и боевой (production) контуры реализовано с помощью встроенного механизма **Terraform Workspaces**:

1. **Динамическое именование**: Изоляция ресурсов в рамках одного каталога Яндекса достигнута путем добавления встроенной переменной `${terraform.workspace}` в параметры `name` всех создаваемых компонентов. Это полностью исключает конфликты и коллизии имен при параллельном существовании контуров.
2. **Разделение состояний (State)**: Terraform автоматически изолирует слепки инфраструктуры друг от друга. Файлы состояний для каждого окружения сохраняются в отдельные служебные директории, исключая случайное затирание данных:
   * `terraform.tfstate.d/staging/terraform.tfstate`
   * `terraform.tfstate.d/production/terraform.tfstate`

## 🛠️ Описание создаваемых компонентов

1. **Сетевой уровень (`main.tf` / `security.tf`)**:
   * Для предотвращения исчерпания лимитов сетевых квот аккаунта конфигурация переведена на использование существующих облачных ресурсов: стандартной сети `default` и подсети `default-ru-central1-d`.
   * Настроена группа безопасности `sg-${terraform.workspace}`, динамически открывающая входящие порты для SSH (22), HTTP (80), HTTPS (443) и разрешающая весь исходящий трафик.

2. **Кластер веб-серверов (`count-vm.tf`)**:
   * С помощью конструкции `count` разворачиваются **2 идентичные виртуальные машины** (`web-${terraform.workspace}-1` и `web-${terraform.workspace}-2`) на базе платформы `standard-v3`.
   * Чтобы уложиться в жесткие квоты суммарного объема HDD-дисков в зоне `d`, тип загрузочных дисков изменен на быстрый `network-ssd`. Включен NAT (`nat = true`) для получения публичных IP-адресов из интернета. Машины работают в прерывистом режиме (`preemptible = true`).

3. **Кластер баз данных (`for_each-vm.tf`)**:
   * С помощью конструкции `for_each` и списка объектов `vm_resources_list` разворачиваются **2 кастомные ВМ** для СУБД с уникальными именами, привязанными к воркспейсу.
   * Размер дисков увеличен до минимальных для Ubuntu 5 ГБ и 10 ГБ, тип дисков изменен на `network-ssd`. Доля CPU (`core_fraction`) установлена на 20% под требования платформы v3. 
   * **Важно:** Во избежание превышения лимита квот на публичные IP-адреса (`vpc.externalAddresses.count`), внешние адреса для баз данных отключены (`nat = false`). Они общаются с веб-серверами строго внутри локальной сети.

4. **Выделенное хранилище данных (`disk_vm.tf`)**:
   * Создается **3 сетевых HDD диска** (`disk-${terraform.workspace}-X`) по 1 ГБ каждый через `count`.
   * Разворачивается ВМ `storage-${terraform.workspace}` (платформа v3, core_fraction 20%, `nat = false`), к которой через динамический блок `dynamic "secondary_disk"` монтируются все 3 диска. Установлена явная зависимость запуска от готовности баз данных (`depends_on`).

5. **Вывод данных (`output.tf`)**:
   * Автоматически выводит в терминал структуру с именами, ID и FQDN всех успешно поднятых серверов конкретного окружения.

## 🚀 Инструкция по управлению окружениями

### 1. Подготовка
1. Поместите исполняемый файл `terraform.exe` версии 1.5.7+ в корень проекта.
2. Сгенерируйте актуальный IAM-токен командой `yc iam create-token` и обновите его в файле `terraform.tfvars`.
3. Убедитесь в наличии SSH-ключа по пути, указанному в `variables.tf`.
4. Инициализируйте проект:
   ```powershell
   ./terraform init
   ```

### 2. Развертывание окружения Staging
```powershell
# Создание и переход в воркспейс staging
./terraform workspace new staging

# Проверка плана и применение конфигурации
./terraform plan
./terraform apply
```

### 3. Развертывание окружения Production
```powershell
# Создание и переход в воркспейс production
./terraform workspace new production

# Применение конфигурации для боевого контура
./terraform apply
```

### 4. Полезные команды
* Проверить список существующих окружений: `./terraform workspace list`
* Переключиться на нужное окружение: `./terraform workspace select <имя>`
* Уничтожить инфраструктуру конкретного окружения: `./terraform destroy`
