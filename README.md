# Домашнее задание: Описание инфраструктуры в Yandex.Cloud с помощью Terraform

В данном репозитории описана отказоустойчивая, масштабируемая инфраструктура для приложения в Yandex.Cloud. Вся конфигурация разделена на логические файлы и адаптирована под современную зону доступности `ru-central1-d` (Калуга).

## Описание создаваемых компонентов

1. **Сетевой уровень (`main.tf` / `security.tf`)**:
   * Для предотвращения исчерпания лимитов квот аккаунта используется существующая облачная сеть `default` и подсеть `default-ru-central1-d`.
   * Настроена группа безопасности `example_dynamic`, открывающая входящие порты для SSH (22), HTTP (80), HTTPS (443) и разрешающая весь исходящий трафик.

2. **Кластер веб-серверов (`count-vm.tf`)**:
   * С помощью конструкции `count` разворачиваются **2 идентичные виртуальные машины** (`web-1` и `web-2`) на базе платформы `standard-v3`.
   * Для успешного прохождения квот по общему объему HDD дисков в зоне `d`, диски переведены на быстрый тип `network-ssd`. Использован прерывистый режим (`preemptible = true`) для экономии средств.

3. **Кластер баз данных (`for_each-vm.tf`)**:
   * С помощью конструкции `for_each` и переменной-списка объектов `vm_resources_list` в `variables.tf` разворачиваются **2 кастомные ВМ** с уникальными характеристиками CPU и RAM для СУБД (`db-vm-1` и `db-vm-2`).
   * Размер дисков увеличен до минимально разрешенных Яндексом 5 ГБ и 10 ГБ, тип дисков изменен на `network-ssd`. Доля CPU (`core_fraction`) установлена на 20% в соответствии с требованиями платформы v3.

4. **Выделенное хранилище данных (`disk_vm.tf`)**:
   * Создается **3 сетевых HDD диска** (`disk-0`, `disk-1`, `disk-2`) по 1 ГБ каждый.
   * Разворачивается ВМ `storage`, к которой с помощью динамического блока `dynamic "secondary_disk"` подключаются все 3 созданных диска. Установлена зависимость запуска от доступности баз данных (`depends_on`).

5. **Вывод данных (`output.tf`)**:
   * Описан автоматический вывод сетевых имен, ID и FQDN всех созданных виртуальных машин в терминал после применения скрипта.

## Как запустить проект локально
1. Поместить исполняемый файл `terraform.exe` в корень проекта.
2. Сгенерировать OAuth-токен в консоли Яндекса и заполнить файл `terraform.tfvars`.
3. Убедиться в наличии SSH-ключа по указанному в переменных пути.
4. Выполнить команду инициализации: `terraform init`
5. Применить конфигурацию: `terraform apply`
